## Project Vision

The objective of this project is to investigate whether bird vocalizations can be transformed into meaningful three-dimensional structures that reveal characteristics of sound which are difficult—or impossible—to observe using traditional spectrograms alone.

Instead of treating bird songs as waveforms or two-dimensional frequency plots, every recording becomes a spatial object whose geometry is generated from measurable acoustic properties.

The ambition is not to create artistic interpretations, but scientifically grounded visualizations where every visual element originates from real acoustic data.

If successful, each bird song becomes an interactive three-dimensional acoustic manifold that can be explored, compared and analysed from multiple perspectives.

⸻

## Inspiration

This project is inspired by experimental work demonstrating that bird songs can be represented as dynamic three-dimensional networks generated from acoustic analysis.

These examples show that:

* Audio recordings can be sampled continuously through time.
* Acoustic features can be translated into spatial coordinates.
* Individual data points form evolving three-dimensional structures.
* Different bird species appear to generate recognizable geometric patterns.
* Multiple individuals can occupy the same acoustic space, allowing direct comparison.

These works demonstrate that meaningful spatial representations of bird vocalizations may exist and provide the conceptual inspiration for this project.

## Reference Implementation Analysis

A set of example visuals from an existing reference project ("Seeing Birdsong") were reviewed to reverse-engineer the likely underlying schema. This is not a specification for our project, but a documented starting point reacted to and diverged from.

**Confirmed project details (correction, 2026-07-21):** "Seeing Birdsong" is by artist Lucio Arese, in collaboration with filmmaker Thibault Noirot. Arese's own name for the underlying model is the **"Spatiotemporal Acoustic Manifold."** Rendering is done in TouchDesigner, navigating precomputed datasets in real time — see the architectural note below.

**Stated pipeline (per the reference project's own summary):**
1. Signal processing
2. Feature extraction
3. Dimensionality reduction

**Per-point data schema observed:**

| Channel | Variable | Notes |
|---|---|---|
| Color | Most active frequency band at emission time | Consistent across single-recording views |
| Size | Signal amplitude (scaled 0–1) | Consistent across all examples |
| Lifetime | Seconds since emission, animated | Points are born, persist, and fade |
| Emission time | Seconds from start of animation (Time = 0) | Anchors playback/animation |
| Position (x,y,z) | Either (a) a direct physical mapping driven by amplitude/frequency/time, or (b) a dimensionality-reduced embedding of a multi-dimensional feature vector | Two distinct approaches observed — see below |
| Edges/connections | Temporal adjacency (consecutive frames) | Not a similarity graph — a literal path through time |

**Two distinct geometry-generation strategies observed:**

- **Physical/oscillatory mapping** — position generated by a formula driven directly by amplitude, frequency, and time.
- **Feature-vector embedding** — **40 Mel-Frequency Cepstral Coefficients (MFCCs)** extracted per frame, then reduced to 3D. This is the approach used in the multi-individual comparison examples, where several recordings are projected into one **shared** embedding space.

**Correction (2026-07-21):** the feature set is now confirmed as 40 MFCCs. This supersedes the earlier guess — inferred from screenshots alone — of an 8-axis spectral descriptor set (spectral centroid, spread, entropy, crest, slope, frequency modulation, amplitude modulation, tonality). That 8-axis guess should be read as a retired hypothesis about the *reference* project, not a claim ever adopted for this project's own pipeline.

**Open tension worth flagging (not resolved here):** WP1's literature review found MFCCs reported to outperform other engineered feature families for birdsong specifically, including under noisy conditions (HierBirdFeat2023, `04_Literature/Literature_Database.md`) — consistent with Arese independently landing on MFCCs. Yet this project's own WP2 benchmark found MFCCs failed the mandatory negative control on our specific dataset, at both 22 samples (Experiment 001) and 150 samples (Experiment 003) — see D-010 in `07_Decision_Log/Decision_Log.md`. Both findings are real and currently unreconciled: it may be dataset-specific (recording conditions, species mix, sample size), a difference in how MFCCs were computed/parameterized, or something else. Recorded here as an open question for a future literature/methodology pass, not something to resolve now.

**Architectural convergence note:** TouchDesigner navigating a precomputed dataset in real time is architecturally the same shape as this project's own adopted approach (offline Node.js feature extraction + PCA, then live browser rendering/navigation via react-three-fiber — see `06_Technical_Architecture/Technical_Architecture.md`). This project arrived at that offline-compute/live-navigate split independently, through its own WP2/WP3 benchmarking process (the computational cost of feature extraction and PCA over raw spectrograms is what drove the split), not by copying Arese's implementation.

**Attribution note:** this project's visual style is inspired by Arese's public work on "Seeing Birdsong." The underlying techniques — MFCCs, PCA, spectral embeddings, point-cloud rendering — are standard, publicly-documented signal-processing and visualization methods, not anyone's proprietary invention. This project's specific implementation, dataset, validation process (negative controls, benchmarking, Project Rules 001–003), and end goal (ecological monitoring, not an art installation) are independently developed and distinct from Arese's piece. This project does not claim Arese's specific creative execution as its own, and does not present itself as his work.

## Research Principles (new in v0.4 Final)

Development Philosophy and Decision Principles state *how work gets prioritized and evaluated*. This chapter states *what kind of science the project is trying to do* — the scientific culture underneath both.

This framework prioritizes:

* Falsifiable hypotheses over attractive explanations
* Reproducibility over novelty
* Measurable evidence over intuition
* Transparency over complexity
* Scientific usefulness over visual appeal

Every major claim produced by this framework should ultimately be testable through independent experiments. A result that cannot in principle be shown wrong is not yet a scientific claim, however compelling it looks.

⸻

## Core Philosophy

Every visual element should represent measurable information. Nothing should exist solely for aesthetic purposes.

If a point exists, it represents measurable acoustic data. If a connection exists, it represents a meaningful relationship. If clusters emerge, they should arise naturally from similarities within the recordings rather than artistic design decisions.

**Visual channel convention:**

- Position → feature-space embedding (shared across a comparison set)
- Color → frequency band (single-recording views) *or* individual/group identity (comparison views)
- Size → amplitude
- Edges → temporal adjacency

Any departure from this convention requires its own data justification.

⸻

## Decision Principles (revised in v0.4)

Whenever multiple technically valid solutions exist, recommendations are evaluated against these priorities, in order:

1. **Empirical validity** — backed by tested evidence (not just internally consistent reasoning)
2. **Internal methodological consistency** — sound methodology even where not yet empirically tested
3. **Transparency** — the pipeline and data provenance can be inspected
4. **Explainability** — a non-expert can understand why a given output looks the way it does
5. **Reproducibility**
6. **Long-term maintainability**
7. **Extensibility**
8. **Computational efficiency**
9. **Visual clarity**

Visual appeal alone should never justify a scientific decision.

**Empirical validity and internal consistency were split out from a single "Scientific validity" item, and Transparency/Explainability were split from a single item, because they are genuinely different failure modes and were getting conflated.**

## Validation Strategy (new in v0.4)

Validation is a first-class, mandatory component — not an optional add-on once visuals exist.

**Project Rule 001:** No labels may participate in embedding generation or dimensionality reduction whenever the objective is to evaluate natural clustering or similarity. If labels (species, individual, season, etc.) inform how the embedding is fit, any resulting "separation" is not a finding — it's circular. Labels may only be used *after* an unsupervised embedding is fit, to color/inspect the result.

**Mandatory negative controls:** Every validated pipeline must be run on shuffled or synthetic random data and confirmed to *not* produce clean-looking clusters or structure. Dimensionality-reduction methods (UMAP, t-SNE, and related techniques) are documented in other fields to sometimes produce visually convincing structure from data that has none — an active methodological debate exists around this in other domains that rely on the same tools (e.g. single-cell biology), and it applies directly here. If random input produces tidy-looking clusters, the pipeline is broken and no downstream claim can be trusted until that's fixed.

**Other validation questions to answer before treating outputs as scientific findings:**
* Can the same individual consistently produce nearby manifolds?
* Can different species naturally separate (under Project Rule 001)?
* Can seasonal changes be detected?
* Can habitat restoration produce measurable differences?
* Do similarity scores correlate with existing bioacoustic metrics?
* Do results agree with expert biological interpretation (inter-rater/expert agreement check)?

**Additional validation steps:** held-out or cross-validated testing for any separation claim; inter-rater/expert agreement between manifold-derived conclusions and independent expert interpretation of the same recordings.

## Scientific Success Criteria (revised in v0.4)

Success criteria must resolve to an objective statistical measure, not a stated hope. Current criteria, with the measurement requirement made explicit:

* Species naturally cluster → *quantified via a metric such as Adjusted Rand Index or silhouette score, with a pre-committed threshold*
* Individuals consistently group with themselves → *quantified similarly*
* Seasonal averages reveal statistically meaningful differences → *quantified via an appropriate significance test*
* Monitoring locations develop repeatable acoustic fingerprints → *quantified via a reproducibility metric across repeated sampling*
* Independent experts find the outputs useful → *quantified via structured expert review, not informal feedback*
* Results remain reproducible → *quantified via repeat-run consistency*

**Adopted rule:** every success criterion must eventually have an objective statistical measure and a stated threshold before it counts as a validated result. The exact metrics are not yet fixed — that determination is itself a pending decision (see Open Decisions).

## Scientific Assumptions (expanded in v0.4)

Current assumptions:

* Bird vocalizations contain stable acoustic structure.
* Similar vocalizations should occupy nearby positions.
* Average manifolds represent meaningful biological information.
* Spatial differences may reflect ecological differences.
* Long-term monitoring may reveal environmental change.

**Newly added assumption (previously hidden):** that extracted acoustic features are more sensitive to a bird's actual vocal behavior than to *recording conditions* — microphone type, distance, background noise, habitat acoustics. Nothing in the current design separates "this manifold differs because the bird sounds different" from "this manifold differs because the recording setup was different." This is a direct confound risk for every seasonal, spatial, and cross-location comparison the framework intends to support, and needs its own investigation before those comparisons are trusted.

This chapter should be continuously updated throughout the project as new assumptions surface or existing ones are tested and either confirmed or retired.

## Known Limitations (new in v0.4 Final)

Stated explicitly, as a mature research proposal should, rather than left implicit:

* Unknown whether 3D is the optimal target dimensionality (see "Why 3D?" in Open Decisions).
* Unknown whether manifolds preserve biological meaning at all, as opposed to encoding recording-condition artifacts or embedding-algorithm artifacts.
* Unknown whether the currently inherited feature set is sufficient or appropriate.
* Unknown whether geometric similarity in the manifold corresponds to actual ecological similarity.
* Unknown robustness to recording conditions (microphone, distance, habitat acoustics) — see the recording-condition confound noted in Scientific Assumptions above.

These limitations do not block proceeding to the benchmarking/validation phase — they define what that phase needs to resolve.

⸻

## Failure Criteria (new in v0.4 Final)

Scientific Success Criteria state what would count as success. This chapter states the complementary question: **what would convince us the methodology is wrong?** A framework without stated failure conditions cannot be falsified, and per Research Principles above, an unfalsifiable claim is not yet a scientific one.

The methodology is considered to have failed, in whole or in relevant part, if:

* Random or shuffled data produces manifolds with structure similar to real data (i.e. the mandatory negative control fails — see Validation Strategy).
* Recording condition (e.g. microphone type) explains more variance in the manifold than species or individual identity does.
* Repeated recordings of the same individual/song do not cluster together more closely than recordings of different individuals.
* Independent experts, given the manifolds, cannot distinguish differences that correspond to real, known biological or ecological differences.

Any one of these outcomes should trigger a documented methodology review, not a quiet adjustment of thresholds until the result looks acceptable.

## Average Acoustic Manifolds — Resolved Methodology

**Precondition:** don't average raw coordinates directly. Fit one shared dimensionality-reduction model across the pooled feature vectors of every recording being combined, then project each recording into that shared space (subject to Project Rule 001), so everything lands in one comparable coordinate system before any averaging happens.

**Adopted approach: density-cloud (KDE) representation.** Overlay all recordings in the shared space and represent the group as a fuzzy volumetric cloud — dense/bright where songs consistently occupy the same acoustic territory, thin/faint where they diverge. This degrades gracefully (unlike alignment-based averaging, which can be confidently wrong with no visible warning sign) and directly encodes song variability as a visible property, which doubles as a candidate ecological indicator in its own right.

**Recorded alternatives (not adopted, kept on record):**
* Time-aligned averaging (DTW) — align by internal song structure, then average matched positions into a single clean trajectory. More rigorous once feature extraction and segmentation are validated, but depends on trusting the alignment.
* Simple time-bin centroid averaging — average by percentage-through-the-song regardless of content. Cheaper, cruder, useful as an early prototyping fallback.

## Open Decisions Pending Benchmark / Literature Review (new in v0.4)

These are decisions the project has explicitly deferred rather than pinned prematurely, because pinning them now would mean guessing.

### Embedding Benchmark (adopted approach — supersedes earlier "pin one algorithm now" recommendation)

The framework should initially support multiple embedding algorithms — PCA, UMAP, t-SNE, and other candidates — rather than committing to one in advance. The purpose is not to permanently support every algorithm, but to experimentally determine which produces the most scientifically useful representation. Only after benchmarking should one become the documented, pinned default used for production comparisons (required for the "repeatable/comparable" design principles).

### Information Preservation Reporting

Every dimensionality reduction method used must be accompanied by a quantitative measure of how much information was preserved and how much was discarded. The specific metric depends on the algorithm — explained variance where applicable (PCA-style methods), or reconstruction error, trustworthiness, continuity, or neighborhood preservation for nonlinear methods (UMAP, t-SNE). This generalizes the earlier "report explained variance" note so it doesn't assume a linear method.

### The "Why 3D?" Question

Explicitly unresolved: is three dimensions the right target for the reduced representation, or an assumption inherited from "humans like rotating objects" rather than from the data? 2D might be sufficient; higher dimensions might preserve meaningfully more information at the cost of direct visualizability. This should be tested as part of the Information Preservation reporting above, not assumed.

The framework should strive to be: data-driven, scientifically transparent, repeatable, standardized, explainable, scalable, comparable through time, comparable across locations, and flexible enough to accommodate future scientific developments. ## Research Questions vs. Engineering Questions (split in v0.4 Final)

These were previously mixed together as "Scientific Questions." They are separated here because they have different resolution paths: research questions are resolved by evidence about biology; engineering questions are resolved by benchmarking and implementation choices.

### Research Questions

* Does biology create stable, meaningful acoustic manifolds?
* Can seasonal changes be detected through average acoustic manifolds?
* Can individuals be distinguished using geometry alone?
* Can habitat restoration influence acoustic structure over time?
* Can spatial variation between acoustic traps be quantified?
* Can long-term monitoring reveal gradual ecological change?
* Can species develop consistent geometric fingerprints?
* Can variability itself become a measurable ecological indicator?

These remain hypotheses to be investigated, with an explicit mandate that each eventually resolves to a statistical measure (see Scientific Success Criteria) and, per Research Principles above, a stated way it could be shown false (see Failure Criteria below).

### Engineering Questions

* Which embedding algorithm should be used (see Embedding Benchmark)?
* Which acoustic feature set should be used?
* Which segmentation methodology should be used?
* Which renderer/rendering approach should be used?
* Which interpolation/smoothing policy should be default?

These are resolved through benchmarking, prototyping, and implementation trade-offs, not through biological evidence — though the choice made can affect which research questions can be trusted (e.g. a poor feature set can mask a real biological signal).

## Long-Term Vision

The ultimate objective is not simply to visualize bird songs. The long-term ambition is to investigate whether acoustic manifolds can become standardized, comparable and scientifically meaningful representations of biodiversity that support ecological monitoring, scientific research and future Nature Positive reporting — and align, where appropriate, with emerging formal disclosure standards such as TNFD/ISSB.
