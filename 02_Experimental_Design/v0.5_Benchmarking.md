# Bird Song Spatial Visualization Framework

**Experimental Design & Benchmarking Plan**

*Companion document to the Master Project Document (v0.4 Final)*

**Version: 0.5**

This document does not modify the conceptual framework in v0.4 (Final), which remains stable. It operationalizes it: v0.4 defined what is known, assumed, undecided, and how decisions will eventually be validated. This document defines *how* the currently open decisions (D-004, D-009, D-010 in the Living Decision Log, plus the acoustic-feature and validation questions raised throughout v0.3–v0.4) will actually be resolved with evidence.

Reviewed and converged between Claude and ChatGPT with no open disagreements prior to drafting. WP1 (Literature Review) has been populated with an initial pass of real findings, drawn from published bioacoustics and animal-vocalization literature — see WP1 section below and Sources at the end of this document. WP2 and WP3 candidate lists have been updated accordingly. This is a first pass, not exhaustive — treat WP1 as open to a further round if ChatGPT's own literature search surfaces additional relevant work.

⸻

## Experimental Philosophy

The objective of this phase is not to prove the framework correct. The objective is to design experiments capable of proving it either correct or incorrect.

Every experiment in this plan should be able to answer: *what evidence would increase confidence in the framework, and what evidence would reduce confidence in it?*

This phase deliberately prioritizes learning over confirmation. Negative results — a feature set that fails to separate known species, an embedding that fails the negative control, a segmentation approach that doesn't hold up against expert-annotated boundaries — are documented with the same rigor as positive findings, and are treated as legitimate outputs of this phase, not failures of it.

⸻

## Project Rule 002 (new in v0.5)

**No implementation decisions without a benchmark plan.**

If the response to "let's use UMAP" is not immediately followed by "compared to what, on which metric, on which subset of the data," the decision is not ready to be made. Same for feature sets, segmentation methods, and averaging methodology. This rule applies retroactively to any decision in the Living Decision Log still marked "Pending benchmark" or "Open."

⸻

## Dataset Status (new in v0.5)

The project has an existing, real dataset to run these work packages against:

* **Size:** 100+ recordings.
* **Structure:** includes repeat recordings of the same identified individuals, and/or repeat visits to the same site/season — this is what makes Level 2–4 analysis (individual, species, location averaging) testable at all, rather than purely theoretical.
* **Label provenance:** species/individual identification comes from BirdNET plus two additional models, each with an associated confidence level. This is **model-consensus verification, not independent human expert verification.**

**Flagged risk (feeds directly into WP1 and WP5 below):** because labels originate from acoustic classifiers, there is a circularity risk if this project's chosen feature set or embedding ends up correlating strongly with whatever internal representation those classifiers use. A "species cluster" result validated only against model-derived labels does not yet distinguish "our manifold captures real biology" from "our manifold recovers the same acoustic cues BirdNET already uses." This does not block using the dataset — it means the validation plan (WP5) needs a way to probe for this specifically, rather than treating model-consensus labels as unquestionable ground truth.

**Open items to confirm before WP4 can be finalized:**
* Number of distinct species and individuals represented, and their distribution (is it balanced or dominated by a few common species?).
* The confidence-level thresholds used when accepting a BirdNET/model label, and whether a lower-confidence subset should be excluded or analyzed separately.
* Whether any subset of the dataset could feasibly get an independent human expert spot-check, even a small one, to at least partially decouple validation from model-consensus labels.
* Metadata available per recording: microphone/recorder type, distance, location, date/season — needed to test the recording-condition confound flagged in v0.4's Scientific Assumptions.

## WP1 — Literature Review (findings, first pass)

**Question this closes:** D-010 (Acoustic Feature Set) and part of the label-provenance risk above.

### Finding 1: there are three distinct, established strategies for turning bird vocalizations into a spatial representation — not one

The literature converges on three genuinely different approaches, each with real precedent, rather than one obvious default:

**(a) Engineered acoustic feature vectors.** Compute a fixed set of hand-designed descriptors per frame/syllable (spectral centroid, MFCCs, spectral contrast, entropy, etc.), then reduce or compare directly. Multiple birdsong classification studies report MFCCs specifically as consistently strong performers relative to other engineered features for birdsong (a hierarchical birdsong feature extraction study directly concluded MFCCs outperformed alternative feature families for birdsong under noisy conditions). This is the closest match to the reference project's own 8-axis feature set, and the inherited feature list (spectral centroid, spread, entropy, crest, slope, tonality, frequency/amplitude modulation) sits within this same family, though it hasn't itself been benchmarked against MFCCs specifically.

**(b) Raw spectrogram frames fed directly into dimensionality reduction, with no hand-designed features at all.** This is the approach used in a well-established, peer-reviewed pipeline (Sainburg, Thielk & Gentner, 2020, *PLOS Computational Biology*, and the companion practical-guide paper by Thomas et al., 2022, *Journal of Animal Ecology*): each vocal element is spectrogrammed, the spectrogram is flattened into a numeric vector, and that vector — not a hand-picked feature list — goes straight into UMAP. This sidesteps the "which features?" question entirely, at the cost of losing direct interpretability of any single axis. Notably, this exact pipeline has already been applied across birdsong specifically and is reported to recover individual identity and species identity in the resulting projections for multiple bird datasets — which is direct precedent that this project's core ambition is achievable with a known, published method.

**(c) Learned embeddings from a pretrained deep model** (e.g. BirdNET's own internal representation, or a VAE trained on spectrograms). BirdNET specifically produces a 1024-dimensional embedding from the second-to-last layer of an EfficientNetB0-style network, and at least one published ecology paper has already used exactly these BirdNET embeddings — not BirdNET's species predictions — as a general-purpose unsupervised feature space for acoustic event clustering.

### Finding 2: option (c) directly compounds this project's label-circularity risk — this is a real, not hypothetical, concern

Because this project's existing dataset was labeled using BirdNET plus two other models, using BirdNET's own embeddings as the acoustic feature set (option c) would mean the same underlying representation both produced the labels and produced the manifold geometry. Any "species separates" finding under that setup would be near-tautological. **Recommendation: option (c) using BirdNET-family embeddings specifically should be excluded from WP2, or included only as a deliberately-labeled negative/comparison case, not a candidate for adoption.** A VAE trained from scratch on this project's own data (not BirdNET's) would not carry this specific risk, though it introduces its own new question (does the VAE, unsupervised, over-fit to recording conditions instead of biology).

### Finding 3: UMAP is repeatedly reported to recover individual identity in bird/animal vocalization data — with a caveat that matters for the averaging methodology (D-001)

The same Sainburg et al. line of research reports that UMAP projections capture individual identity for several species and datasets — encouraging for Level 2 (Individual Bird) analysis specifically. However, a separate, more cautionary line of research (on mouse ultrasonic vocalizations specifically) argues that not all vocal repertoires cluster into discrete, well-separated groups the way birdsong tends to — vocal diversity can fall along a continuum instead. This is a direct piece of supporting literature for the v0.4 decision to adopt density-cloud (KDE) averaging over discrete-cluster assumptions: it's not yet established that this project's dataset *will* cluster cleanly, and the chosen methodology should not assume it will.

### Finding 4: automated syllable/phrase segmentation is a solved-enough problem to build on, not something to invent from scratch (feeds D-009)

Multiple established approaches exist, spanning a simplicity/accuracy trade-off:
* Classic amplitude/energy-thresholding segmentation — simple, no training required, but sensitive to noise and threshold tuning.
* TweetyNet (a published, open neural-network model for automated syllable annotation, validated across Bengalese finch and canary song) — reported to reliably reproduce known findings about song syntax from automated annotations alone, and represents a strong, ready-to-use candidate rather than something to build in-house.
* More recent real-time/self-supervised approaches (e.g. a 2025 sliding-window neural segmentation system, reported at ~98% precision/recall against manually verified boundaries in Bengalese finches) show the field is still actively improving on this, but the older TweetyNet-style approach is mature enough to prototype with immediately.

**Recommendation for D-009:** prototype with an existing, published segmentation tool (TweetyNet or an amplitude-threshold baseline) rather than developing a bespoke segmentation method — this is squarely an engineering question (per the Research/Engineering Questions split in v0.4) with a mature off-the-shelf answer, not a place to spend novel research effort.

### Finding 5: the UMAP/t-SNE cluster-illusion debate (flagged in v0.4) is real, ongoing, and specifically about whether apparent structure reflects the data or the algorithm

The relevant methodological literature (centered on a debate in single-cell biology, e.g. Chari & Pachter's critique and the responses to it) does not resolve cleanly in either direction: critics argue these methods can make dissimilar structures look similarly "clustered," while responses argue that — used with the right validation metrics (trustworthiness, neighborhood preservation, and comparison against a proper negative control) — the methods do preserve real local structure rather than manufacturing it from nothing. The practical upshot for this project is exactly what v0.4's Failure Criteria and mandatory negative control already require: don't trust a clustering-looking result without running the negative control and reporting a preservation metric alongside it.

### Output of WP1: updated candidate shortlist for WP2/WP3

* **Feature sets to benchmark (WP2):** MFCCs; the inherited 8-axis spectral-descriptor set; raw flattened spectrograms (no hand-designed features, per Sainburg/Thomas et al.); a from-scratch VAE embedding (not BirdNET-derived).
* **Excluded from WP2 as a live candidate:** BirdNET-family embeddings, due to the label-circularity risk in Finding 2 — retained only as a labeled comparison case to illustrate the risk, not a candidate for adoption.
* **Segmentation approach to prototype first (D-009):** TweetyNet or amplitude-threshold baseline, not a bespoke method.
* **Averaging methodology (D-001):** literature supports keeping density-cloud (KDE) as the adopted default rather than assuming discrete clustering will hold — no change to the v0.4 decision, but now with direct supporting precedent.

## WP2 — Feature Extraction Benchmark

**Question this closes:** D-010 (Acoustic Feature Set).

Candidates to compare (per WP1 findings above):
* MFCCs (literature-reported as a strong, consistent performer specifically for birdsong)
* Spectral descriptors (centroid, spread, entropy, crest, slope — the set inherited from the reference project, treated as one candidate among several rather than a default)
* Raw flattened spectrograms fed directly into dimensionality reduction, with no hand-designed feature step at all (the Sainburg/Thomas et al. approach — a genuinely different strategy, not a variant of the above two)
* A from-scratch VAE embedding, trained on this project's own recordings (not a pretrained BirdNET-family model)

**Explicitly excluded from this benchmark:** BirdNET-family embeddings as the project's feature set. Since this dataset's labels were produced using BirdNET plus two other models, adopting BirdNET's own embedding as the feature space would mean the same representation both assigns the labels and generates the manifold — a direct instance of the label-circularity risk flagged in Dataset Status and WP1 Finding 2. May be run once as a deliberately-labeled comparison case to illustrate the risk concretely, but is not a candidate for adoption.

Evaluation approach: compare candidates against each other using the Information Preservation metrics defined in v0.4 (explained variance / reconstruction error / trustworthiness / continuity / neighborhood preservation, as appropriate per method), and against the negative-control requirement (Project Rule 001/mandatory negative controls) before any candidate proceeds to WP3.

## WP3 — Embedding Benchmark

**Question this closes:** D-004 (Embedding Algorithm Selection).

Candidates: PCA, UMAP, t-SNE, with PHATE or other manifold-learning methods as a stretch candidate if time allows.

Evaluation approach: run each candidate against the feature set(s) surviving WP2, with labels excluded from fitting per Project Rule 001. Score using Information Preservation metrics and the "Why 3D?" question from v0.4 — report results at 2D, 3D, and a higher-dimensional option to test whether 3D is actually where the useful information lives or just a rendering convenience.

Mandatory: run the full negative control (shuffled/synthetic data) through every candidate before treating any of them as validated.

**Note per WP1 Finding 3:** don't assume the dataset will resolve into discrete, well-separated clusters. Some published animal-vocalization datasets do cluster cleanly; others show continuous variation instead. The benchmark should evaluate embeddings on how well they preserve real structure (whatever form it takes), not on whether they produce visually tidy clusters — a method can score well on Information Preservation while still describing a continuum, and that would be a legitimate finding, not a failed embedding.

## WP4 — Validation Dataset

**Question this closes:** operationalizes the dataset described above into a concrete evaluation split.

To finalize once the open items above are confirmed:
* Define train/benchmark vs. held-out subsets — held-out data should not inform any feature or embedding choice made in WP2/WP3.
* Decide how (if at all) confidence-level stratification is used — e.g. primary validation on high-confidence-label recordings only, with lower-confidence recordings analyzed separately to see if results degrade as expected.
* If a human expert spot-check subset is feasible, carve it out specifically to address the label-circularity risk, since it would be the only fully independent ground truth available.
* Document exactly which recordings have repeat-individual or repeat-site structure, since that subset is what makes Level 2–4 testing (D-001, average manifolds) possible at all.

⸻

## WP5 — Statistical Evaluation

**Question this closes:** Scientific Success Criteria and Failure Criteria from v0.4 — this is where they get actual numbers attached.

Candidate metrics: Adjusted Rand Index, silhouette score, F-score (against model-consensus labels, with the circularity caveat noted), trustworthiness, neighborhood preservation.

This work package should explicitly test each Failure Criterion from v0.4, not just each Success Criterion:
* Does the negative control (random data) fail to produce structure? (must pass before anything else is trusted)
* Does recording condition (e.g. device/location metadata, once available per the WP4 open items) explain more variance than species/individual identity?
* Do repeat recordings of the same individual cluster together more tightly than recordings of different individuals?
* Where a human expert spot-check subset exists (WP4), does expert judgment agree with manifold-implied differences?

**Only after WP1–WP5.** Build a working version using whichever feature set and embedding algorithm survived benchmarking, on the finalized validation split, reporting the WP5 statistics as the prototype's actual evidence base — not as a separate "does it look good" exercise.
